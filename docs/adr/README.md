# Architecture decision records

Each ADR records a real decision, the alternatives considered, and the
consequences. They are numbered and immutable once accepted; a reversal is a new
ADR that supersedes an old one.

1. Layered package with downward-only dependencies
2. Provider-scoped identifiers
3. Knowledge-time feature contract
4. Non-uniform match clock
5. Canonical attacking pitch frame
6. Optional torch dependency
7. Verifier separate from the result summariser
8. Synthetic sample data, labelled, for the demo
9. Dixon-Coles over plain Poisson for scores
10. Deep Sets for the spatial encoder
11. Era-specific rules as data, not code branches
12. Atomic checkpoint writes for recovery
13. Coverage counted from identity sets
